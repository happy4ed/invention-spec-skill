# 문체 규칙 — 사람이 쓴 아이디어 제안서로 읽히게

고안 명세서는 출원서가 아니다. 발명자가 조직에 내고 출원 담당자와 논의하기 위해 쓰는 **아이디어
제안서**다. 읽는 사람은 발명자·심사 담당자·변리사다. 아이디어의 새로움이 선명하게 읽혀야 하고,
"AI 나 변리사가 쓴 티"가 나면 안 된다.

## 1. 특허는 쓰는 것이지 증명하는 것이 아니다

```
명세서   어떤 로직으로 어떻게 동작하는가 — 구성과 작동 원리
논문     그게 실제로 효과가 있는가 — 수치 실증
```

- 벤치마크 표, 비교 실험, "실측 결과 ○○% 개선" 같은 서술을 넣지 않는다.
- **왜 이 문제가 생기고 어떤 로직으로 풀리는가**를 인과로 쓴다.
- 수치는 로직을 설명하는 예시로만 쓴다.
  좋은 예: "기준이 강수 확률 60% 일 때 오늘 예보가 70% 면 판단을 켜고, 40% 면 끈다."
  나쁜 예: "시험 결과 오차가 37% 줄었다."

## 2. 평이한 직장인 문어체

| 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| ~하지 아니한다 | ~하지 않는다 |
| ~하고자 함 | ~하려고 한다 |
| ~하는 바, ~함에 있어 | 문장을 나눠 풀어 쓴다 |
| 화상 | 이미지 · 사진 · 화면 (대상에 맞게) |
| 영상 (정지 사진을 가리킬 때) | 사진. `영상`은 동영상이거나 굳어진 분야명(영상처리)일 때만 |
| ~에 있어서 (청구항 인용 밖) | ~에서 · ~할 때 |

- 같은 대상을 같은 말로 부른다. 한 문단 안에서 `사진`·`이미지`·`영상`을 근거 없이 섞지 않는다.
- AI 티를 뺀다: 억지 3연속 나열, 과장 수식("혁신적인", "획기적인"), 분사형 꼬리, 뜻 없는 강조.
- 다만 블로그체·1인칭·개성 주입은 하지 않는다. 담백하고 평이한 것이 맞는 말투다.
- 청구항 초안에도 같은 용어 규칙을 적용한다. 청구항이라고 특허투를 쓸 이유는 없다
  (`상기`, `제N항에 있어서` 같은 청구항 관용 표현은 초안 안에서만 허용).

## 3. 유보 금지 — 단정형으로

명세서는 찾은 것과 우리 발명의 차이를 말한다. **안 찾아진 것은 쓰지 않는다.** 유보가 붙으면 읽는
사람이 발명을 의심한다.

명세서(6절 + 부록)에서 빼는 것:
```
"검토했으나 정면 선행 미발견" · "미조사" · "미열람" · "미확인"
확신도 표기(높음/중간/낮음)
"조사의 한계" 절 · "상위 N건만 확인" 같은 조사 방법 서술
"최종 판단은 변리사 몫" · "애매하다" · "~일 수 있다" · "~로 보인다"
```

명세서에 남기는 것:
```
실제로 청구항을 연 선행 특허 — 번호 · 구성요소 대조표 · 판정
우리 발명이 그와 무엇이 다른가 (차별성)
왜 그 차이가 진보인가 (진보성) — 결합관계와 인과로 단정
```

톤은 "~로 보인다"가 아니라 "~이다", "~할 수 있다"가 아니라 "~한다". 차이의 근거는 열어 본 선행과의
대조로 세우고, 서술은 단정형으로 쓴다. 우리 발명의 구성과 동작은 그렇게 설계했으니 사실로 쓴다.

빼낸 정보(한계·확신도·미결 쟁점·변리사 검토 고지)는 버리지 않고 `prior-art-raw.md` 로 옮긴다.

## 4. 구현 여부로 서술을 나누지 않는다

- 코드에 없는 구성도 발명으로 쓴다. 구현물은 실시예 하나일 뿐이다.
- `[구현]` · `[구상]` · `[미구현]` 같은 태그를 달지 않는다.
- "현 실시예는 ~까지만 한다", "구현하지 않아 효과 미검증" 같은 방어 문구를 붙이지 않는다.
- 예외: 선행조사의 한계는 사실이므로 원자료에 적는다.

## 5. CYA 사족 · 각주 금지

- "최종 판단은 변리사 검토를 요한다", "전수 조사가 아니다" 같은 면책 문장을 본문에 반복하지 않는다.
  필요한 고지는 원자료 첫머리와 인계 메모에 한 번만 둔다.
- 각주·미주를 쓰지 않는다. 특허번호·출처 성격 표시는 본문에 인라인으로 적는다.
- 사족을 지우면서 "특허된다" 같은 빈 단정을 넣지도 않는다. 사실과 차이만 담백하게 쓴다.

## 6. 내부 논의 메모가 새지 않게

- `〔논의 메모〕` 같은 대괄호 메타태그, 작업자 이름, "다음 라운드에서 볼 것", TODO 를 명세서에 남기지 않는다.
- "문언 회피 높음 / 실질 위험 중간" 같은 내부 등급 약칭을 쓰지 않는다. 내용만 본문으로 풀어 쓴다.
- 대화 중 나온 회피 후보·기각된 방향·미결 쟁점은 버리지 않는다. 채택·기각은 부록 D 에,
  미결 쟁점은 원자료 5절에 정리된 문장으로 남긴다.

## 7. 양식 불변

- 조직 양식이 있으면 그 절 구성·표 구조(행·열)·글머리·번호 체계를 바꾸지 않는다. 덧붙일 것은 부록으로 붙인다.
- 실제 내용을 채운 절에서는 양식의 안내 상자(【기재 예】 등)를 지운다. 안내문과 본문이 겹치면 안 된다.
- 번호 체계(1·2 / 가·나·다 / (1)(2) / (a)(b))가 끊기거나 중복되지 않게 한다.

## 8. 인용

- 원문을 옮길 때만 큰따옴표를 쓰고 바로 옆에 출처(문헌번호 · URL · 확인일)를 단다.
- 요약·의역에는 따옴표를 쓰지 않는다.
- 근거가 없는 서술은 쓰지 않는다. 사실(문헌·번호·제품 동작)은 열어 본 것만 쓴다.
