# 검토 게이트 — 넘기기 전에 하나씩

검토는 고치는 사람이 아니라 **지적하는 사람**의 눈으로 한다. 작성 직후의 자기 문장은 맞아 보이기
쉽다. 가능하면 작성 맥락 없이 다시 읽는다(새 세션 · 다른 검토자 · 다른 모델에게 명세서만 주고 지적을
받는 방법도 좋다). 한 항목이라도 걸리면 고친 뒤 다시 돈다. **지적 0건이거나 두 번 연속 새 지적이 없으면 통과.**

## 0. 기계 점검 먼저

```bash
python3 tools/spec_lint.py spec.md --raw prior-art-raw.md --figdir figures
python3 tools/svg_print_pt.py figures/
```
기계 점검은 정독을 대신하지 않는다. 걸린 줄은 문맥을 보고 판단하고, 안 걸렸다고 통과로 보지 않는다.

## 1. 형식

- [ ] 6절(1-가 · 나 · 다, 2-가 · 나 · 다)이 모두 있고 순서가 맞다. **조직 양식을 쓰면 그 양식의 절 구성이
      검토 기준**이다 — 6절 대신 그 양식의 절이 모두 채워졌는지 본다.
- [ ] 청구항 후보 · 초안이 있다(양식에 청구범위 본절이 있으면 그 자리, 없으면 부록 A · B). 대조표 · 회피 ·
      기각 기록(부록 C · D)은 본문이나 첨부에 있다.
- [ ] 도면 목록 · 주요 부호 표가 있고, 본문의 "도 N" 과 부호가 목록과 맞는다.
- [ ] 번호 체계가 끊기거나 중복되지 않는다.
- [ ] 출원 부속(annex.md): 선행특허 목록 · 검토의견(한두 줄) · 발명 내용 표(목적 · 구성 · 효과 · 차이점) ·
      요약 한 문단 · 가장 가까운 종래기술 선정 근거 한 줄.

## 2. 진보성 논리

- [ ] 1-다 가 **왜 문제가 생기는가**를 인과로 쓴다. 효과 주장이 실측 · 벤치마크가 아니라 구성과 로직에 묶여 있다.
- [ ] 2-가 끝에 **구성요소 간 결합관계** — 왜 이 순서여야 하고, 어느 결합을 떼면 뒤가 왜 안 되는가 — 가 있다.
- [ ] 2-다 의 차이 서술이 "선행 <번호>는 X, 본 발명은 Y" 꼴로 핵심 선행마다 있다.
- [ ] 추가 · 치환한 구성마다 `겹친 선행 요소 → 무엇을 바꿨나 → 왜 벗어나나 → 실현 가능 근거` 가 부록 D 에 있다.
- [ ] 실현 불가능한 구성이 없다: 로직 성립 · 입력을 원리적으로 얻을 수 있음 · 모순 없음.
- [ ] 차별성 서술이 "좋다"가 아니라 "다르다"다.

## 3. 청구항 후보 · 초안 · 회피 설계

- [ ] 독립항 1개 이상과 종속항 몇 개가 있고, 구성요소가 단계별로 드러난다.
- [ ] **우리 실시예가 독립항 범위 안에 들어온다**(자기 점검 행이 있다).
- [ ] 대조표에서 갈라지는 자리(선행에 없는 우리 구성요소, 선행 요소 대신 쓰는 적극적 수단, 치환)가 독립항
      문언에 실제로 세워져 있다. 주해에만 있고 문언에 없으면 회피가 아니다.
- [ ] `치환됨` 마다 기능 · 방식 · 효과 중 무엇이 다른지 적혀 있다(균등론).
- [ ] 회피 주장이 **실제로 연 청구항 전문**에 근거한다. 번호 · URL 이 있다.
- [ ] 인용 관계에 순환 · 결번이 없다.
- [ ] 청구범위 계층 표가 있다(최광의 문언 · 한정 계열 · 구체 실시).

## 4. 정직 — 하나라도 걸리면 반려

- [ ] 모든 특허번호에 열람 URL 이 있다(명세서나 원자료). 표본 몇 건을 **직접 다시 열어** 번호 · 명칭 ·
      출원인이 맞는지 확인했다(`tools/gp.py meta <번호>`). 존재하지 않는 문헌이 하나라도 있으면 반려.
- [ ] 독립항 서술이 원문과 맞는다. 표본 한두 건은 원문 독립항과 대조표 요소를 한 줄씩 맞춰 본다.
- [ ] 큰따옴표 인용이 원문 그대로이고 출처가 붙어 있다. 요약에 따옴표가 없다.
- [ ] 제품명 · 서비스 동작 서술도 확인한 것만이다.
- [ ] 근거 없는 단정("등록된다", "권리범위는 ~이다")이 없다. 근거 있는 의견은 정상이다 — 막지 않는다.
- [ ] 조문 · 판례 번호는 직접 확인한 것만 있다.
- [ ] 원자료 첫머리와 인계 메모에 변리사 검토 고지가 한 번씩 있다.
- [ ] 출원 대리 · 완성 청구범위 · 제3자 유상 감정으로 읽히는 서술이 없다.

## 5. 문체 · 유보

- [ ] 명세서에 유보 · 조사 상태 표현이 없다: 미발견 · 미조사 · 미열람 · 미확인 · 확신도 · 조사의 한계 ·
      "~일 수 있다" · "~로 보인다" · 변리사 몫. **원자료에는 있어야 정상이다** — 원자료는 지적하지 않는다.
- [ ] 법률투 · 특허투가 없다(하지 아니한다 · 하고자 함 · 하는 바 · 화상 · 청구항 밖 "~에 있어서").
- [ ] 같은 대상을 같은 말로 부른다.
- [ ] CYA 사족 · 각주 · 내부 메모(대괄호 메타태그 · TODO · 작업자 이름 · 내부 등급 약칭) · 구현 여부 태그가 없다.
- [ ] 양식 안내 상자가 남아 있지 않다.

## 6. 도면 · 문서 산출물

- [ ] 구조도 · 순서도가 있다. 주체가 둘 이상이면 시퀀스도, UX 차별점을 주장하면 와이어프레임이 있다.
- [ ] 도면마다 편집 가능한 원본(.mmd · .svg · .drawio)과 렌더가 `figures/` 에 있다.
- [ ] 인쇄 글자 8pt 이상, 본문 폭 · 쪽 높이 안.
- [ ] 제출본(.docx · .pdf)을 만들었다면 쪽마다 렌더 이미지를 열어 봤다: 그림 여백 초과 · 쪽 걸침 · 표 삐져나감 ·
      셀 잘림 · 글줄 잘림 · 한글 깨짐 · 빈 쪽 0건. 보고에 쪽수 · 그림 수 · 육안 검사 쪽 수 · 잘림 건수를 적었다.

