# 선행기술 조사 — 검색 · 청구항 전문 열람 · 기록

조사의 목적은 두 가지다. 핵심 요지와 **직접 겹치는 선행 특허**를 찾는 것, 그리고 그 독립항을
대조표(element-comparison.md)로 넘기는 것. 평가 축은 **선행 특허 대비** 차별성·진보성이다. 논문은
종래기술 배경과 문제 인식의 근거로만 쓴다.

## 0. 정직성 — 예외 없음

- **실제로 검색해 열어 본 문헌만 쓴다.** 특허번호 · 명칭 · 출원인 · 날짜 · 제품명을 기억이나 추측으로
  쓰지 않는다. 여기서 지어내면 대조표와 진보성 논리 전체가 무너진다.
- **읽지 않은 특허의 청구항을 서술하지 않는다.** 초록만 본 문헌은 대조표에 넣지 않는다.
- 모든 "찾았다 · 확인했다"에는 **특허번호 · URL · 확인일**을 남긴다. 나중에 누구든 다시 열어 볼 수 있어야 한다.
- 원문 인용은 큰따옴표 + 출처. 요약에는 따옴표를 쓰지 않는다.
- 겹침이 없으면 "없음"을 검색식·범위와 함께 원자료에 적는다. 빈손을 성과로 포장하지 않는다.

## 1. 검색식 짜기

1. 핵심 요지를 **입력 · 핵심 처리 · 출력 · 수행 주체**로 쪼갠다.
2. 각 덩어리에 영문 · 국문 동의어와 상위 개념을 붙인다
   (예: `reminder OR alert OR notification`, `smartphone OR mobile terminal OR portable device`).
3. 덩어리끼리 `AND` 로 묶는다. 처음엔 넓게, 결과가 수천 건이면 덩어리를 하나씩 더한다.
4. **흐름 전체를 갖춘 문헌**을 찾는 검색식과, **구성요소별로** 가장 가까운 문헌을 찾는 검색식을 따로 돌린다.
5. 결과에서 자주 나오는 출원인·용어를 다음 검색식에 되먹인다. 같은 출원인의 패밀리 문헌도 확인한다.

## 2. 도구

### Google Patents (기본 소스)
```bash
python3 tools/gp.py search "(umbrella OR parasol) AND (reminder OR alert) AND (mobile OR smartphone)" --num 20
python3 tools/gp.py search "<검색식>" --country KR --after 20150101
python3 tools/gp.py claims <번호> --independent        # 독립항 전문
python3 tools/gp.py claims <번호> --source             # 번역 페이지면 원문 문장으로
python3 tools/gp.py meta <번호> <번호> …               # 부속 ① 목록용 서지
```
- `search` 는 Google Patents 화면이 쓰는 비공개 엔드포인트(`/xhr/query`)를 부른다. 문서화된 API 가
  아니어서 형식이 바뀌거나 막힐 수 있다. 막히면 브라우저로 `https://patents.google.com/` 에서 같은
  검색을 하고 번호만 옮겨 와 `claims` 로 연다.
- `claims` · `meta` 는 공개 특허 페이지 `https://patents.google.com/patent/<번호>/<언어>` 를 읽는다.
  비영어 문헌의 `/en` 페이지는 기계 번역이다. 판정은 원문(`--source` 또는 `/ko` · `/zh` 등)으로 확인한다.
- 짧은 시간에 수십 번 부르면 구글이 자동 조회를 막는다(HTTP 503, 'Sorry' 페이지). 막히면 수십 분
  쉰다. 검색식을 다듬어 호출 횟수를 줄이고, 여러 건을 열 때는 건 사이를 띄운다.
- 도구 없이도 같은 일을 할 수 있다: 웹 검색이나 브라우저로 Google Patents 를 열고, 특허 페이지의
  Claims 절을 읽는다.

### 그 밖의 소스
- **국내 문헌 전용 DB(KIPRIS 등)** 는 이 스킬의 도구가 지원하지 않는다. 웹 화면에서 직접 검색할 수는
  있고, 스크립트로 조회하려면 해당 서비스의 API 키가 필요하다. 쓰지 못했으면 "국내 문헌 전용 DB 미사용"을 원자료 4절에 한계로 적는다
  (Google Patents 가 수록한 국내 문헌은 검색된다).
- **Espacenet** 은 자동 조회를 막는 확인 절차가 있어 스크립트 조회가 잘 되지 않는다. 필요하면 브라우저로 연다.
- 논문(Google Scholar 등)과 제품 자료는 명세서에서는 1-나 · 1-다 의 배경 서술에만 쓴다. 다만 비특허
  문헌도 실제 심사에서는 신규성 · 진보성 판단에 쓰이므로, 발명과 가까운 것을 찾았으면 원자료에 남기고
  출원 담당자에게 알린다.

## 3. 무엇을 열어 보나

검색 결과마다 제목 · 출원인 · 우선일만 보고 1차로 거른 뒤, 남은 것의 **독립항 전문**을 연다.

| 단계 | 기준 |
|---|---|
| 1차 거르기 | 입력 · 핵심 처리 · 출력 중 둘 이상이 같은 자리에 놓였는가, 또는 우리 핵심 구성요소 하나와 같은 수단을 쓰는가 |
| 독립항 열람 | 1차 통과분 전부. 독립항이 여럿이면 방법 · 장치 · 매체 독립항을 모두 본다 |
| 대조표 상대 | 흐름 전체를 갖춘 것, 그리고 우리 구성요소별로 가장 가까운 것 |
| 명세서 열람 | 독립항이 넓게 쓰였거나, 우리 발상의 동기를 명세서에서 개시했을 때 |

우리 발상을 청구항이 아니라 **명세서 본문에서 개시**한 문헌도 진보성 판단에는 영향이 있다. 그런 문헌도
청구항까지 열어 본 뒤, 대조표가 아니라 1-나 종래기술과 부록 D 기각 사유에 반영한다.

## 4. 기록 — prior-art-raw.md

조사하는 동안 바로 기록한다. 나중에 몰아서 쓰면 URL 과 확인일이 빠진다.

- **검색 기록**: 일자 · 소스 · 검색식 · 결과 수 · 열어 본 문헌.
- **열람 문헌**: 번호 · 명칭(원문) · 출원인 · 우선일 · 연 범위(독립항 전문 / 명세서 / 초록만) · URL · 확인일.
- **판정별 확신도**: 대조표 판정마다 높음 · 중간 · 낮음과 남은 의문.
- **한계**: 쓰지 못한 DB, 기계 번역에 의존한 문헌, 열람 범위.
- **청구항 후보별 대조**: 후보마다 겹치는 문헌이 있는가(어느 구성이 겹치나) / 없는가(어떤 검색식으로 봤나).

명세서에는 이 중 **실제로 청구항을 연 선행 특허와 그 대조 결과만** 옮긴다. 나머지는 원자료에 남는다.

## 5. 찾은 것이 없거나 열리지 않을 때

- **직접 겹치는 선행이 없으면**: 대조표는 구성요소별로 가장 가까운 문헌으로 만든다. 부속 ②의 종래기술도
  그중 목적 · 입력 · 출력이 가장 가까운 것을 고른다. 검색식과 열람 범위는 원자료에 남긴다.
- **도구가 막히면**: 브라우저나 웹 검색으로 같은 문헌 페이지를 열어 Claims 절을 읽는다. 그래도 원문을
  못 열면 그 문헌은 대조표에 넣지 않고 원자료에 "원문 미확보"로 남긴다.

## 6. 조사 결과를 넘기는 형식 (라운드 보고용)

```
핵심 요지: <한 줄>
직접 겹치는 선행: <번호 — 무엇이 겹치나> (없으면 "없음, 검색식 n개 · m건 열람")
대조표 요지: <번호별로 `없음` 이 나온 구성요소>
회피 후보: <2~3개, 장단>
다음 라운드 검색 계획: <무엇을 더 볼 것인가>
```
