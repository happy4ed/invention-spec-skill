# 도해 지침 — 구조도 · 순서도 · 시퀀스도 · 와이어프레임

말로 설명하고 끝내지 않는다. **도면이 없는 명세서는 미완성이다.** 출원 담당자가 그대로 받아 고쳐 쓸
수 있도록 **생성·편집 가능한 원본**으로 만든다. 본문을 쓰는 동안 도면도 같이 만든다. 본문이 끝난 뒤
붙이려 하면 도면 없이 넘어가는 일이 생긴다.

## 1. 최소 구성

| 도면 | 언제 | 내용 |
|---|---|---|
| 구조도 | 항상 | 전체 구성요소(부호 포함)와 데이터 흐름 |
| 순서도 | 항상 | 핵심 처리의 단계별 흐름 — 분기 · 반복 · 종료 조건 포함 |
| 시퀀스도 | 주체가 둘 이상일 때 | 사용자 ↔ 단말 ↔ 서버 ↔ 외부 서비스의 시간 순 상호작용 |
| 와이어프레임 | UX 차별점을 주장할 때 | 그 판단이 화면에서 어떻게 드러나는가 |
| 대비도 | 선택 | 선행과 본 발명의 흐름 차이를 나란히 |
| 결합관계도 | 선택 | 어느 결합을 떼면 뒤 단계가 왜 성립하지 않는가 |

## 2. 형식 우선순위 — 위에서부터 시도

```
1  Mermaid (.mmd)     순서도 · 시퀀스 · 상태도 · 단순 구조도. 텍스트라 고치기 쉽다. 기본값.
2  SVG (손으로 쓴)     좌표·배치가 중요한 구조도, 와이어프레임. 텍스트 편집 가능한 벡터.
3  draw.io (.drawio)  박스가 많아 사람이 손으로 재배치할 도면.
4  이미지 (PNG)        위 셋으로 도저히 안 되는 것만. 그래도 반드시 만들어 넣는다 — 빈칸으로 두지 않는다.
                      쓸 수 있는 이미지 생성 도구가 있으면 그것으로라도 만든다.
```

렌더 예:
```bash
npx -y @mermaid-js/mermaid-cli -i figures/fig02-flow.mmd -o figures/fig02-flow.svg
npx -y @mermaid-js/mermaid-cli -i figures/fig02-flow.mmd -o figures/fig02-flow.png -s 3
```

## 3. 규칙

- 도면마다 **번호(도 1, 도 2 …)와 제목**을 붙인다. 명세서 본문은 번호로 참조한다("도 2 의 S3 단계").
- 명세서 첫머리 `도면의 간단한 설명` 표에 **번호 · 제목 · 내용 · 파일명**을 적는다.
- 구조도의 박스에는 `도면의 주요 부호` 표와 같은 **부호(10, 20 …)** 를 단다. 본문 구성요소 소제목의
  부호와 맞춘다.
- 원본(.mmd · .svg · .drawio)과 렌더(.svg · .png)를 `figures/` 에 함께 둔다. 열어 보기만 해도 보여야 한다.
- 도면은 명세서와 일치해야 한다. 그림에만 있는 기능을 넣지 않는다.
- 파일명은 `figNN-<짧은영문>.<확장자>` 로 통일한다.

## 4. 문서에 넣을 크기 — 잘림 0

본문 폭은 `용지 폭 − 좌우 여백` 이다. A4(210mm)에 여백 15mm 면 180mm. 쓰는 양식의 여백 값을 읽어서 쓴다.

```
가로   본문 폭을 넘지 않는다
세로   한 쪽 높이를 넘지 않는다. 두 쪽에 걸쳐 잘리지 않게
비율   가로세로 비율 유지 — 한쪽만 늘리면 글자가 찌그러진다
긴 도면  축소하면 판독이 안 된다 → 가로로 눕히거나 · 나눠 싣거나 · 축소 뒤 판독 가능한지 확인
캡션   그림 바로 아래. 그림과 캡션이 다른 쪽으로 갈라지지 않게
```

**인쇄 글자 크기.** SVG 의 viewBox 폭을 본문 폭과 같은 pt 값으로 잡고(180mm = 510.24pt) 그림을 본문 폭
그대로 넣으면, SVG 안의 `font-size` 가 곧 종이 위 pt 가 된다(변환 기준 등 다른 크기 지정이 없을 때).
**최소 8pt.** 넣기 전에 검사하고, 넣은 뒤 렌더해서 다시 본다.

```bash
python3 tools/svg_print_pt.py figures/ --width-mm 180 --max-height-mm 260 --min-pt 8
```

글자를 줄여 맞추지 말고 **박스 수를 줄인다.** 세부는 다른 도면과 본문이 맡는다.

**워드에 넣는 형식.** SVG 를 바로 넣지 못하면 PNG(600dpi)로 넣는다. SVG→EMF 변환은 둥근 모서리
테두리가 빠지거나 아래가 잘리는 일이 있으니 넣은 뒤 렌더해 확인한다.

## 5. 와이어프레임

- 손으로 쓴 SVG 나 간단한 HTML/CSS 를 헤드리스 브라우저로 캡처해서 만든다. 회색조 박스와 실제 문구면 충분하다.
- 화면 한 장마다 **무엇이 새로운가**를 도면 옆 설명이나 본문에 한 줄로 적는다. 그 신규 요소가 청구항
  후보(부록 A)의 어느 항목을 뒷받침하는지 맞춰 둔다.
- 선택지 순서 · 확인 단계 · 다시 묻기처럼 시간에 따라 바뀌는 UX 는 화면 여러 장을 시퀀스로 잇는다.
- 실제 제품 화면을 베끼지 않는다. 비교할 타사 화면은 실제로 확인한 것만, 출처와 함께 쓴다.

## 6. 문서 렌더 육안 검사 — "확인했다"로 끝내지 않는다

```bash
soffice --headless --convert-to pdf --outdir out/ spec.docx
pdftoppm -r 110 -png out/spec.pdf out/page
# out/page-*.png 를 한 장씩 열어 본다
```

쪽마다 본다: 그림 여백 초과 · 그림 쪽 걸침 · 표 삐져나감 · 셀 잘림 · 글줄 잘림 · 한글 깨짐 · 빈 쪽.
표는 전체 폭이 본문 안, 셀은 줄바꿈(잘려서 "…" 금지), 한 행이 쪽 경계에서 갈라지지 않게, 쪽이
넘어가면 머리행 반복. 특허번호·URL·수식이 줄 밖으로 나가지 않게 줄바꿈을 허용한다.

보고에는 `쪽수 · 넣은 그림 수 · 육안 검사한 쪽 수 · 잘림 건수(확인 방법)` 를 적는다.
여러 건을 만들 때는 **한 건을 육안 검사까지 끝낸 뒤** 나머지를 같은 방식으로 돌린다.
`.md` 가 진본이고 `.docx` 는 제출본이다. 내용을 바꾸면 `.md` 를 고치고 다시 변환한다.
